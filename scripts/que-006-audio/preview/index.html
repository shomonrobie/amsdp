How to review

  1. Play each of the 20 samples below. They are byte-for-byte concatenations of the delivered clips — no re-encoding, no trimming, no loudness change.
  2. Compare what you hear with the caption. The caption is produced by the product's own buildAnnouncement(), not typed here.
  3. Open the clip timeline (▸) if a sample sounds wrong; it names the exact clip and pause at each position, so a defect can be reported against one asset.
  4. Use the live composer to hear any token or room number you like, including the ones you were not expecting.
  5. Record pass / fail per sample in the review template, and say which asset is at fault when a sample fails.

What this preview does not prove

  • Approval. Playing a sample here is not approval. The manifest stays pending until a human signs the review record.
  • Product integration. The app does not play these clips yet; this page composes them itself, exactly as documented, outside product code.
  • Room-number range. The catalogue records 1–999 as a recommendation awaiting owner approval, not a rule. The composer guards at 9 digits for both token and room and refuses longer input rather than inventing a limit.
  • Trim and pause. Each delivered clip keeps its recorded trailing silence — up to ~1.15 s in the Bangla set — which is why Bangla samples run much longer than English ones. Removing it would change the delivered files, so it is reported, not fixed.
  • Device. Playback here uses this machine's default output. Clinic hardware still has to be tested by ear.
